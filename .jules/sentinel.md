## 2025-03-27 - [Fix Command Injection Risk in spawnProcess]
**Vulnerability:** The `spawnProcess` utility in `src/verify/formal.ts` explicitly enabled `shell: process.platform === "win32"` when spawning `java`. If user-influenced arguments like TLC configurations or module names contained shell metacharacters (e.g., `&`, `|`), they could be executed by the Windows command shell (`cmd.exe`).
**Learning:** `shell: true` is rarely necessary for well-known executables like `java` that don't rely on batch wrappers (`.bat` or `.cmd`). Relying on the shell for argument parsing introduces unnecessary and severe command injection risks.
**Prevention:** Always default to `shell: false` when using `spawn`. Only enable it if absolutely necessary (e.g., executing a `.bat` file on Windows), and in those cases, rigorously sanitize all inputs.
## 2024-05-18 - Fix Windows Command Injection via cmd.exe escaping

**Vulnerability:** Command injection vulnerability discovered in `src/verify/formal.ts` where arguments for native processes (e.g., `java` and `.cmd` wrappers) on Windows were improperly wrapped in double quotes `""` when passed to `cmd.exe /c` using `windowsVerbatimArguments: true`. Since `cmd.exe` does not interpret `\"` as an escaped quote, an argument containing `test" & calc.exe & "` allowed arbitrary command execution on Windows platforms.
**Learning:** Node.js's `windowsVerbatimArguments: true` bypasses built-in escaping, forcing developers to manually escape arguments for `cmd.exe`. Simply wrapping arguments in double quotes `""` and using `.replace(/"/g, '\"')` is insecure because `cmd.exe` only toggles quote states and treats internal separators `&` outside of quotes as new commands.
**Prevention:** When using `windowsVerbatimArguments: true` with `cmd.exe /c`, strictly use caret (`^`) escaping for all shell metacharacters (e.g., `&`, `|`, `<`, `>`, `(`, `)`, `^`, `%`) *before* wrapping the individual argument in double quotes. The double quotes will then safely pass the characters to the underlying program (like `npm.cmd` or `java.exe`) while the carets protect them from being evaluated by `cmd.exe` itself.
## 2024-05-24 - [CRITICAL] Prevent Prototype Pollution in Config Parsers
**Vulnerability:** Prototype pollution vulnerability in `src/config.ts`'s `setValueByDotPath` and `deepMerge` functions. Untrusted object keys could overwrite `__proto__`, `constructor`, or `prototype`, allowing attackers to modify global object prototypes.
**Learning:** Config parsers and deep merge utilities are common vectors for prototype pollution in JavaScript/TypeScript if they don't explicitly filter dangerous keys.
**Prevention:** Always add safety guards to explicitly reject or skip `__proto__`, `constructor`, and `prototype` in custom object traversal and merge functions.
